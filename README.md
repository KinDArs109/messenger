# Мессенджер

Монорепо. Пока готов бэкенд: аутентификация и каркас реального времени.

```
apps/server        Express 5 + Socket.io + Prisma
apps/web           React 19 + Vite + Tailwind 4
packages/shared    типы и схемы валидации для сервера и клиента
```

**Запуск:** `npm run dev` поднимает оба приложения. Клиент — **http://localhost:5173**

Vite проксирует `/api` и `/socket.io` на бэкенд, поэтому в браузере всё приходит с одного адреса: httpOnly-cookie работает без настройки CORS, а среда разработки совпадает с боевой.

## База данных

PostgreSQL 18 развёрнут **локально**, из архива бинарников — без установщика, без службы Windows и без прав администратора. Лежит в `C:\Users\Admin\pgsql`, данные в `data` рядом.

Сначала база была в облаке (Neon): так было проще начать, когда локально поставить PostgreSQL не получалось. Оказалось, что это встроенная в архитектуру зависимость от заграничного канала — рвётся он, и мессенджер мёртв **для всех**, а не только для владельца ноутбука. Поэтому база вернулась на ту же машину, что и сервер.

Раз службы нет, базу нужно поднимать самому:

```bash
npm run db:up
```

| Команда | |
|---|---|
| `npm run db:up` | поднять базу |
| `npm run db:down` | остановить |
| `npm run db:status` | проверить |
| `npm run check:db` | 40 запросов подряд — не рвётся ли соединение |

Путь к бинарникам переопределяется переменной `PGSQL_HOME`.

## Команды

| Команда | Что делает |
|---|---|
| `npm run build` | собрать клиент в `apps/web/dist` |
| `npm run start` | продакшен: один процесс отдаёт и API, и клиент |
| `npm run dev` | сервер и клиент вместе |
| `npm run dev:web` | только клиент (`-- --host` — открыть с телефона) |
| `npm run dev:server` | только сервер |
| `npm run typecheck` | проверка типов во всех пакетах |
| `npm run db:migrate` | применить изменения схемы |
| `npm run db:seed` | залить тестовые данные (**стирает базу целиком**) |
| `npm run db:studio` | браузерный просмотр базы |
| `npm run db:reset` | снести базу и накатить заново |
| `npm run check:realtime` | 11 проверок WebSocket — требует запущенного сервера |
| `npm run db:cleanup` | убрать брошенные вложения и файлы без записей |
| `npm run db:password -- почта@example.com` | задать новый пароль учётной записи |

> **Про смену пароля.** Забытый пароль восстановить невозможно — в базе лежит только его хеш. Единственный выход — задать новый. Скрипт спрашивает пароль интерактивно и не печатает его на экране; аргументом передавать нельзя намеренно: командная строка видна в списке процессов и остаётся в истории оболочки. Все активные сессии при смене отзываются.

> **Про разрушительные команды.** `db:seed` стирает базу целиком, включая настоящие учётные записи. Он останавливается, если находит пользователей, которых нет в сидах, — продолжить можно только через `-- --force`. `db:cleanup` по умолчанию трогает лишь заведомый мусор; полная зачистка до состояния сидов — через `-- --hard`.

## Что уже работает

**Аутентификация.** Регистрация, вход, обновление и отзыв сессии.

Вход принимает и почту, и имя пользователя — одним полем, а не переключателем: человек не обязан помнить, чем он регистрировался. Различаем по собаке, в логине её быть не может.

**Имя пользователя задаётся один раз и не меняется.** По нему упоминают в сообщениях, находят в друзьях и входят. Смена рвала бы всё это разом: старые упоминания указывали бы в пустоту, а освободившийся логин мог бы занять кто угодно и начать получать чужие уведомления.

**Регистрация закрыта кодом.** Адрес мессенджера виден в интернете, поэтому открытая регистрация означала бы, что учётную запись заведёт любой, кто узнал ссылку. Код задаётся в `SIGNUP_CODE`; пока строка пуста, регистрация открыта — это осознанное поведение по умолчанию для запуска на своей машине, но для публикации наружу код обязателен.

Годится и общий код, и код действующего приглашения: человеку, которому прислали ссылку на сервер, вводить ничего не придётся — код подставится из адреса. Приглашение при этом только проверяется, а расходуется позже, когда человек реально вступает. Сравнение общего кода — `timingSafeEqual`: по времени обычного сравнения короткая строка подбирается посимвольно.

**Подтверждение почты.** После регистрации на адрес уходит шестизначный код. Режим мягкий: без подтверждения мессенджер работает, но сверху висит полоска-напоминание. Жёсткая блокировка на компанию друзей била бы по своим — человек, у которого письмо ушло в спам, оказался бы заперт снаружи.

Код лежит в базе хешем, как и всё, что даёт доступ: дамп не должен позволять войти чужой учётной записью. Живёт пятнадцать минут, пять попыток, между отправками минута — иначе кнопка «отправить ещё раз» превращается в способ засыпать чужой ящик с нашего адреса.

Настройки SMTP необязательны. Без них сервер стартует и работает как раньше: делать их обязательными значило бы ронять весь мессенджер из-за забытой строки в `.env`. Рекомендуемый отправитель — Яндекс: российский, бесплатный, работает без VPN. В `SMTP_PASS` нужен **пароль приложения**, а не пароль от ящика.

**Забыли пароль.** Код приходит письмом, дальше человек задаёт новый — «вспомнить» пароль невозможно, в базе только хеш.

Ответ на запрос кода всегда одинаковый, даже если такой учётной записи нет: иначе форма превращается в способ проверять, зарегистрирован ли конкретный адрес. По той же причине все ошибки на шаге проверки кода дают один текст — разные подсказали бы, на каком шаге подбор идёт правильно.

Успешная смена отзывает все сессии: восстановление пароля чаще всего означает «кто-то мог зайти», и оставлять чужие входы живыми нельзя. Заодно подтверждается почта — человек только что доказал, что письма до него доходят.

Кода из письма, а не ссылки: ссылка требует, чтобы почта открывалась на том же устройстве, где стоит приложение, а шесть цифр можно переписать с телефона руками.

**Вход по одноразовому коду** — второй способ, когда пароль забыт, а почта недоступна. Обычный TOTP из RFC 6238: Google Authenticator и любое совместимое приложение. Реализация своя, тридцать строк на `node:crypto`, — алгоритм не меняется десятилетиями, а зависимость пришлось бы обновлять и доверять ей секрет учётной записи.

Это не второй фактор, а запасной первый, и это осознанный размен: подключая коды, человек соглашается, что доступ к его телефону равен доступу к учётной записи. Поэтому отключение требует пароля — снять защиту тем же кодом мог бы и тот, кто вошёл по украденному.

Секрет создаётся на шаге настройки, но включённым становится только после подтверждения кодом: иначе не успевший добавить ключ остался бы со способом входа, которым не может воспользоваться. Допуск по времени — ±30 секунд: каждый лишний шаг втрое удлиняет окно жизни украденного кода.

- Пароли — Argon2id (пакет с готовыми бинарниками, Build Tools не нужны)
- Access-токен — JWT на 15 минут, живёт только в памяти клиента
- Refresh-токен — в httpOnly-cookie, в базе лежит лишь его SHA-256
- Ротация: при каждом обновлении старый токен отзывается
- Вход с несуществующей почтой занимает столько же времени, сколько с неверным паролем — иначе по задержке ответа можно перебрать, какие адреса зарегистрированы

**Реальное время.** Socket.io с проверкой токена на handshake: неопознанный сокет не создаётся вообще. Комнаты `user:`, `server:`, `channel:`. Статусы «в сети» считают количество вкладок, поэтому закрытие одной из трёх не выкидывает вас в офлайн.

**Общая защита.** Ограничение частоты запросов (жёстче всего на входе), helmet, CORS на один origin, валидация тел запросов через zod, единый формат ошибок.

**Непрочитанное и упоминания.** Каналы с новым выделяются жирным и белой меткой слева, упоминания дают красный счётчик на канале и на сервере в рейле, в ленте появляется черта «новые сообщения». Метка прочтения двигается только вперёд — иначе прокрутка вверх по истории «разчитывала» бы канал обратно.

Упоминания считает сервер, а не клиент: иначе любой мог бы наставить себе и другим любые счётчики. Упомянуть можно только того, кто и так видит канал. Правило разбора `@username` лежит в общем пакете — по нему сервер решает, кому увеличить счётчик, а клиент решает, что подсветить; разойдись они на символ, подсветка была бы там, где уведомления нет.

Отдельное лёгкое событие `channel:activity` доходит до всех участников сервера, а не только до подписчиков канала: без него непрочитанное было бы видно лишь там, куда человек и так смотрит.

**Ответы и реакции.** Ответ показывается одной строкой-цитатой над сообщением, клик по ней прокручивает к оригиналу. Удалённый оригинал не превращается в пустоту — цитата честно говорит, что сообщение удалено. Реакции приходят как «кто, к чему, что», а не готовой сводкой: признак «я тоже нажал» у каждого свой.

**Файлы.** Прикрепить можно кнопкой, перетаскиванием или вставкой из буфера. Загрузка идёт сразу при выборе, пока человек дописывает текст. Картинки показываются в ленте и открываются по клику, остальное — карточкой со скачиванием.

Тип определяется **по содержимому файла**, а не по расширению и не по тому, что заявил браузер: и то, и другое подделывается тривиально. Всё, кроме картинок, отдаётся с `Content-Disposition: attachment` и `CSP: sandbox` — присланный пользователем HTML не должен исполниться в нашем домене и добраться до чужой сессии. Имя на диске генерируем сами, пользовательское только показываем.

**Личные сообщения.** Клик по участнику в списке справа открывает переписку. Личный канал — это тот же `Channel`, только без сервера, с таблицей участников: вся логика сообщений, прав и сокета работает для него без единой правки. Повторный клик открывает существующую переписку, а не заводит новую. Собеседнику она появляется в списке сразу, без перезагрузки.

**Друзья.** Единственный способ начать переписку, не имея общего сервера: раньше написать можно было только тому, кого видишь в списке участников, то есть знакомство всегда начиналось с чужого сервера.

Заявка отправляется по имени пользователя, а не по идентификатору: идентификаторы наружу не показываются нигде, и человеку неоткуда их взять, а логин он видит в упоминаниях и может просто спросить.

Дружба хранится одной строкой на пару, а не двумя зеркальными — две пришлось бы согласовывать вручную, и рано или поздно они разошлись бы: у одного друг есть, у другого нет. Направление заявки считает сервер, каждой стороне уходит свой вариант.

Встречная заявка засчитывается как согласие: заставлять двоих, которые одновременно добавили друг друга, ещё и жать «принять» — бессмысленная церемония. Принять заявку может только адресат, иначе отправитель заводил бы дружбу в одностороннем порядке. Отклонённые не хранятся — строка удаляется, иначе попросить второй раз стало бы невозможно.

**Настройки.** Окно с тремя вкладками: профиль (имя и логин), внешний вид, вход. Настройки внешнего вида лежат в localStorage, а не на сервере: компактная лента уместна на большом мониторе и мешает на ноутбуке, тащить такое между устройствами вредно.

Вкладка «Вход» показывает устройства с активной сессией и даёт отозвать любое, кроме текущего — отзыв текущего был бы выходом, замаскированным под управление устройствами. Ни токена, ни его хеша наружу не уходит: список открывается в браузере, а токен даёт полный доступ к учётной записи. Чужую сессию по подобранному идентификатору не отозвать — поиск идёт строго среди своих, и ответ 404.

**Голосовые каналы.** Клик по голосовому каналу сразу подключает к разговору — заходить в «пустую комнату», а потом искать кнопку «войти» было бы лишним шагом там, где смысл канала ровно один. Состав виден в сайдбаре под каналом, у говорящего подсвечивается аватар, выключенный микрофон помечается. Полоска разговора живёт над панелью пользователя и не исчезает при переходе в другой канал: выйти должно быть можно всегда.

Звук идёт **напрямую между участниками** (WebRTC), сервер его не касается — только сводит людей и передаёт служебные сообщения. Разговор впятером не грузит ноутбук ничем, кроме пары десятков килобайт переписки о том, как соединиться.

Схема «каждый с каждым», без SFU: на десяток друзей это правильный размен — задержка минимальная, а сводить потоки в один негде. На больших компаниях трафик у каждого рос бы линейно, и тогда понадобился бы отдельный сервер.

Список ICE-серверов отдаёт бэкенд, а не зашит в клиенте: появится TURN — его добавят строкой в `.env`, без пересборки клиента и обновления `.exe` у друзей.

> **Честное ограничение.** Пока настроен только STUN, а он лишь подсказывает компьютеру, как тот выглядит снаружи. Когда оба собеседника за CGNAT — а у домашних провайдеров это норма, — прямой путь находится не всегда, и разговор может не состояться. Лечится TURN-ретранслятором, которому нужен сервер с белым IP. Это та же стена, что и с публикацией.

**Что можно делать в клиенте.** Создать сервер и каналы, пригласить по ссылке, писать в личку, писать, править и удалять сообщения, скрывать список участников, выйти. Правка чужих сообщений запрещена всем, включая владельца; удалять чужое может модератор.

**Модерация.** Правая кнопка на участнике — «Выгнать» и «Забанить». Спрятано в меню намеренно: действия редкие и необратимые, и им нечего делать там, где палец промахивается по «написать».

Кик и бан разведены и по смыслу, и по правам: выгнать — это «уйди сейчас», забанить — «не возвращайся». Кик ничего не запрещает, выгнанный вернётся по той же ссылке; бан — отдельная запись, которая переживает выход и проверяется до всего остального при переходе по приглашению. Иначе бан не значил бы ничего.

Трогать можно только тех, кто ниже по роли, и никогда себя: «выгнать себя» — это выход, у него другая кнопка. Сообщения выгнанного остаются: переписка — общая история, и вычищать её задним числом значит переписывать разговор, в котором участвовали другие.

**Приглашения друзьям.** В том же окне под ссылкой — список друзей, которых ещё нет на сервере, и кнопка «Позвать» у каждого. Приглашение уходит обычным личным сообщением со ссылкой, а не отдельной сущностью «приглашение»: у получателя не появляется ничего нового, он видит сообщение от друга и переходит по ссылке ровно так же, как если бы её переслали из другого мессенджера. Ни новой таблицы, ни нового экрана — три существующих запроса подряд.

**Приглашения.** Ссылка вида `/invite/<код>` — единственный способ впустить кого-то на сервер. Предпросмотр открыт без входа: человек видит, куда его зовут, прежде чем заводить учётную запись, а после регистрации вступает без второго клика по ссылке. Срок жизни и число использований ограничиваются.

**Сообщения.** История с курсорной пагинацией по ULID (не OFFSET — он линейно замедляется с глубиной прокрутки), отправка, правка, мягкое удаление. Новое сообщение создаётся обычным POST и рассылается подписчикам канала через сокет.

## Публикация

**Сборка и запуск.** В продакшене клиент отдаёт тот же процесс, что и API, — один адрес, один порт, никакого CORS:

```bash
npm run build
```

```bash
npm run start
```

Адреса вроде `/invite/abc123` существуют только в браузере, поэтому всё, кроме `/api`, `/uploads` и `/socket.io`, отдаёт оболочку приложения. Иначе обновление страницы на приглашении давало бы 404.

**Устанавливается как приложение.** Есть манифест и service worker: Chrome и Edge предложат «Установить», и мессенджер откроется отдельным окном со своей иконкой в панели задач. Работает на Windows, Mac и Android одинаково — без `.exe`, без подписи кода, без предупреждений SmartScreen.

Service worker намеренно не кэширует скрипты и стили. Агрессивный кэш — классический способ намертво залипнуть на старой версии после выкладки; пока сервис обновляется по десять раз в день, цена такой ошибки выше выигрыша.

**Наружу — CloudPub.** У домашних провайдеров обычно CGNAT: роутер сам сидит за NAT, и проброс порта не работает. Туннель устанавливает соединение изнутри, поэтому белый IP не нужен.

Сначала пробовали Cloudflare Tunnel — он умирал через 47 секунд, потому что канал уходил за границу. CloudPub — российский аналог ngrok с российской же инфраструктурой, и по этой причине держится: **95 проверок за 312 секунд, ни одного сбоя**, задержка 65–160 мс.

Бесплатного тарифа хватает с запасом: постоянный поддомен (не меняется при перезапуске), автоматический сертификат Let's Encrypt, WebSocket, 250 ГБ трафика в месяц.

```bash
clo set token ВАШ_ТОКЕН
```

```bash
clo register http 3001
```

`register`, а не `publish`: зарегистрированные туннели поднимаются одной командой `clo run` — это и делает автозапуск.

> **Ссылку раздавать осторожно.** Регистрация в мессенджере открытая: аккаунт заведёт любой, кто получит адрес.

> **Проверять доступность надо на друзьях, а не на себе.** С включённым VPN вы смотрите на сервис из другой страны и о том, что увидят друзья, не узнаете ничего.

## Приложение для рабочего стола

```bash
npm run dist --workspace @messenger/desktop
```

На выходе два файла в `apps/desktop/release`:

| | |
|---|---|
| `Мессенджер-установка.exe` | **рекомендуемый.** Ставится один раз в профиль пользователя, без прав администратора, сам создаёт ярлыки |
| `Мессенджер-portable.exe` | запускается без установки — для тех, кому нельзя ставить программы |

**Как отдать файл другу.** Сервер раздаёт установщик сам: `/download` — обычная сборка, `/download/portable` — без установки. Без входа, иначе получался бы замкнутый круг: чтобы поставить приложение, надо сначала в него войти. Файл лежит по тому же адресу, который знают только приглашённые.

Внутри тот же клиент, что открывается в браузере; отдельной сборки под десктоп нет и не нужно. Смысл оболочки в другом — своё окно, своя иконка в панели задач и отсутствие адресной строки, из-за которой приложение выглядит как сайт.

**Почему установщик, а не portable.** Portable-файл — это самораспаковывающийся архив: при **каждом** запуске он выкладывает 330 МБ во временную папку. Замеры на этой машине: portable — 6,4 с до окна, установленная версия — 0,8 с. Пять лишних секунд и треть гигабайта на диск каждый раз — слишком дорогая плата за «не надо устанавливать», поэтому portable остался запасным вариантом, а не основным.

Адрес сервера зашит по умолчанию, но лежит в `config.json` рядом с настройками пользователя и меняется из меню: туннель может переехать, и требовать ради этого пересборку у каждого друга — плохая идея.

Страница не получает доступа ни к Node, ни к внутренностям Electron (`contextIsolation`, `sandbox`, без `nodeIntegration`): оболочка не должна давать сайту больше прав, чем даёт обычный браузер. Переходы на чужие домены уходят в системный браузер — внутри окна без адресной строки из чужого сайта уже не выбраться.

> **SmartScreen будет ругаться.** Файл не подписан: сертификат подписи кода стоит десятки тысяч рублей в год. Друзьям придётся нажать «Подробнее» → «Выполнить в любом случае». Альтернатива без предупреждений — установка через браузер: Chrome и Edge предложат «Установить», и приложение появится отдельным окном со своей иконкой без единого `.exe`.

## Панель управления

Ярлык **«Мессенджер»** на рабочем столе открывает панель: три индикатора состояния (база, сервер, туннель), кнопки запуска и остановки для каждого слоя, публичный адрес с копированием и переключатель автозагрузки. Ни одного окна консоли — все команды панель запускает скрытыми процессами.

WinForms из [scripts/panel.ps1](scripts/panel.ps1), а не Electron: панель должна открываться мгновенно и не тащить за собой полтораста мегабайт рантайма ради четырёх кнопок. Устанавливать нечего — всё уже есть в Windows.

**Крестик прячет окно в трей, а не закрывает приложение.** Панель остаётся фоновым процессом и продолжает показывать состояние в подсказке иконки. Настоящий выход — стрелка на панели задач, правая кнопка по иконке, «Закрыть».

Выход из панели не трогает сами сервисы. Это стоило отдельной правки: `Start-Process` привязывает запущенное к времени жизни родителя, и туннель умирал вместе с панелью — сайт отдавал 503, хотя база и сервер были живы. Поэтому сервисы стартуют через `WScript.Shell.Run`: так процесс остаётся жить сам по себе. Панель — пульт, а не хозяин.

Опрос идёт каждые две секунды и только локальными проверками — открытый порт, живой процесс. Любой сетевой запрос в этом цикле подвешивал бы интерфейс на время ответа.

> Файл `panel.ps1` обязан лежать в **UTF-8 с BOM**. Windows PowerShell 5.1 читает скрипты без BOM в системной кодировке, и весь русский текст в интерфейсе превращается в мусор.

## Автозапуск

В автозагрузке Windows лежит ярлык не на сервисы, а на **саму панель** — [scripts/panel-boot.vbs](scripts/panel-boot.vbs). Она запускается скрыто, уходит в трей и поднимает всё остальное сама. Так у запуска один хозяин: состояние в трее с первой секунды соответствует действительности, а не догоняет чужой скрипт.

Порядок соблюдается по-настоящему: панель ждёт, пока база начнёт принимать соединения, и только потом стартует сервер. «Запустили» и «принимает соединения» — разные моменты, и на холодном старте между ними уходят секунды; без ожидания сервер падал бы и поднимался сторожем по второму кругу.

Планировщик заданий для этого не нужен: ярлык в автозагрузке работает без прав администратора и виден глазами, а не спрятан в системном реестре.

**Панель запускается в одном экземпляре.** Защита — именованный мьютекс: процессов `powershell.exe` в системе много, и отличить свой от чужого по имени нельзя. Повторный клик по ярлыку не заводит вторую иконку в трее, а показывает окно уже работающей панели — через именованное событие, а не поиск окна по заголовку: после запуска из автозагрузки окно не показывалось ни разу, дескриптора у него нет, и находить нечего.

**Перезапуск после падения** держит [scripts/serve-loop.ps1](scripts/serve-loop.ps1) — сторож на два десятка строк: запускает сервер, ждёт его завершения, поднимает заново. Пять падений подряд быстрее чем за полминуты — цикл останавливается, потому что бесконечный перезапуск только прячет причину.

Здесь раньше был `pm2`, и он работал. Убран по одной причине: его демон на Windows открывает собственное окно консоли, которое нечем спрятать и которое возвращается, если закрыть. Для приложения, которое должно тихо жить в трее, это неприемлемо, а всё, чем pm2 был здесь полезен, уместилось в цикл `while`.

Проверить вручную:

```bash
wscript scripts/panel-boot.vbs
```

> **Ноутбук не должен засыпать.** Спящая машина для друзей неотличима от выключенной. В параметрах питания поставьте «Никогда» для сна при работе от сети.
